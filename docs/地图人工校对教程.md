# 地图人工校对：删岛、改轮廓、新增地区

最重要的一句话：**编辑 `art-source/atlas-editable.svg`，保存后运行 `pnpm atlas:build`。不要直接改网页生成的 JSON，也不要改 JPG。**

这套工作流适合不写代码的日常制图：用 Inkscape 修改 SVG，工具负责重新生成 Three.js 面片、海岸线和地区分界。原来的节点数据单独保存，不会跟着地形自动移动。

## 1. 先认识三个文件

| 文件 | 用途 | 是否直接编辑 |
| --- | --- | --- |
| `art-source/atlas-editable.svg` | 当前地图母版，包含接缝补绘 | **是，平时只改它** |
| `art-source/atlas-reference.svg` | 本次矢量化后、补绘前的留档 | 否，保留用于对照 |
| `public/assets/atlas.svg` / `atlas-regions.json` | 网页使用的显示图与几何数据 | 否，由命令生成 |

地图母版尺寸是 **9216 × 1900**。横向 `0–8192` 是原有地图，`8192–9216` 是新增接缝过渡。原有地图的坐标没有挪动，旧节点仍使用原来的坐标。

补绘是 AI 助手编写的矢量海岸延展，不是原作已有地理，也不是从图片里“恢复”的隐藏内容。它被单独记录在 [接缝说明](seam-extension.md) 中。

## 2. 第一次准备

1. 安装 [Inkscape](https://inkscape.org/release/)。用它打开母版 SVG，不要导入为图片。
2. 在 Finder 中给 `atlas-editable.svg` 复制一份备份，例如 `atlas-editable-before-2026-10-22.svg`，放到你自己的备份目录。
3. 在项目文件夹打开终端。已有 `node_modules` 时不用再运行 `pnpm install`。
4. **只有首次使用制图命令时**，需要 Python 3.11 或更新版本。先运行 `python3 --version` 检查，然后：

```bash
pnpm atlas:setup
```

此命令在项目内创建独立的 `.venv-atlas` 制图环境，不改系统 Python。以后不必重复安装。如果终端找不到 Python，请先从 [Python 官网](https://www.python.org/downloads/macos/) 安装，再重新打开终端。已经有合适的环境时，也可以设置 `ATLAS_PYTHON` 指向其中的 Python。

启动预览：

```bash
pnpm dev
```

在浏览器打开终端给出的地址。给地址加上 `/vector-review.html`，就能打开原图／矢量对照页。例如开发服务器是 `http://localhost:5173`，对照页就是 `http://localhost:5173/vector-review.html`。

## 3. 每次修改只走这六步

1. 在对照页放大，找到要修的岛屿。拖动「对比分界」，检查原图和矢量的差别。
2. 点击右侧矢量色块，会显示 `region-xxx` 编号，方便记录。新增对象可能显示 Inkscape 自动分配的 ID。
3. 在 Inkscape 打开 `art-source/atlas-editable.svg`。若一点就选中整张图，先在「对象」菜单取消编组一次，再选择单独的色块。
4. 按下面相应的方法修改，保存为 **普通 SVG（Plain SVG）或 Inkscape SVG**，仍保存到 `art-source/atlas-editable.svg`。
5. 在项目终端运行：

```bash
pnpm atlas:build
```

6. 等待命令成功，刷新地图和对照页，分别看浅色、深色、最大放大倍率。满意后再提交。

编译会检查闭合路径、自交、重叠、几何和左右接缝。若报错，先根据提示回到 Inkscape 修正。不要把报错当成已经更新成功。

## 4. 删除一座假岛

### 岛屿是一个独立对象

- 用选择工具点中岛屿，确认选框只围住这座岛。
- 按 Delete，然后保存、运行 `pnpm atlas:build`。
- 海岸线会一起重新计算，不需要再去删第二条描边。

### 同一个对象里包含多座岛

有些 SVG path 有多个独立子轮廓。直接 Delete 会一起删除。

- 在节点工具（`N`）中框选**那一座岛的全部节点**再删除；或者先使用「路径 → 拆分」，再选中目标岛删除。
- **有内湖的对象不要随意拆分**：拆分可能把孔洞变成填色对象。若出现湖泊被填满，立即撤销，再使用节点工具只删目标轮廓。
- `region-001`、`region-002` 同时包含跨环绕边缘的补绘部分，不要把它们误当成多余碎岛。

## 5. 改海岸线、大小或位置

### 拉动轮廓

1. 选中目标岛屿，按 `N` 切换节点工具。
2. 拖动节点可以改位置；拖动曲线段或节点手柄可以改变弯曲程度。
3. 少量、局部修改，避免一次对整张图执行大幅简化。
4. 轮廓必须保持闭合，不能打结或自相交。

参考：[Inkscape 节点工具说明](https://inkscape-manuals.readthedocs.io/en/latest/editing-paths.html)。

### 整座岛移动／缩放

用选择工具操作对象即可。导入工具支持 SVG 的平移、旋转和缩放变换，但**不要改变整张文档的画布尺寸或 viewBox**。

移动一座岛之后，要单独检查上面的城市节点；节点不会自动跟着岛走。

## 6. 新增一座岛、切掉一部分、挖内湖

### 新岛

- 在空海域用贝塞尔／钢笔工具画一个闭合轮廓，最后点回起点。
- 选一种接近邻近地区的原图颜色，例如 `#b2dbcb`、`#cff6e0`、`#daefec`。
- 填色必须是纯色、100% 不透明。不要只画描边，不要使用渐变、蒙版、滤镜、位图或文字。
- 不必手工生成 `region-xxx` 名称，Inkscape 自动分配的唯一 ID 也可以。

### 切掉一块海岸／挖湖

- 在目标地块上方画一个闭合的「切割形状」。
- 同时选中地块和切割形状，使用「路径 → 差集」。上面的形状会从下面的地块扣除。
- 切割形状完全位于内部时，结果就是一个内孔；编译工具会保留这个孔。
- 不要仅在陆地上盖一个白色矩形假装删除：两个填色对象会重叠，编译会拒绝。

## 7. 修改两个地区之间的边界——最容易出错

不要只拉动 A 的边界、放着 B 不管；那会产生夹缝或重叠。对新手，更稳妥的是用一块闭合的「转移区域 T」做布尔运算。

例如把 **B 的一小块划给 A**：

1. 在 B 内部画 T，让 T 与 A 当前边界接触或稍微相交，但不要超出 A∪B 的外轮廓。
2. 原位复制 T，保留两份完全相同的形状；暂时锁住不用的那份，避免误选。
3. 用第一份 T 与 B 做「差集」，得到 B−T。
4. 解锁第二份 T，与 A 做「联合」，得到 A∪T。
5. 恢复 A、B 原本的填色，确认没有残留 T，保存并编译。

这样两边使用的是同一块转移形状，边界才会严丝合缝。若涉及三块以上交会、特别细的通道，建议先备份并分多次操作。

编译会拒绝有面积的重叠；**它无法判断一条新出现的白色细缝究竟是你故意画的海峡还是误操作**，所以仍要在对照页放大人工检查。

参考：[Inkscape 路径布尔运算](https://inkscape-manuals.readthedocs.io/en/latest/boolean-operations.html)。

## 8. 改色与合并碎色块

- 只改颜色：修改对象的填色即可。网页海岸线与内部边界会自动重建，Inkscape 的描边设置不决定网页线宽。
- 合并两个同属一地的碎块：选中后使用「路径 → 联合」，再指定最终填色。
- 仅把两个相邻对象涂成同色，仍会保留一条区域分界；想删掉这条内部线，需要真正联合路径。
- 当前约定 `#ffffff` 为水域／白色轮廓，深色模式会按海水显示，不要用纯白表示需要着色的陆地。

## 9. 节点的人工校对

地图地形与节点是两层不同的数据：

- 地形：`art-source/atlas-editable.svg`。
- 节点：`src/nodes.ts`。

在网页点 `NODE EDITOR`，在新位置点一下，便能复制包含 `x`、`y` 的节点代码。坐标范围现在是 `x: 0–9216`、`y: 0–1900`。新增节点粘贴到 `manual` 数组；已有节点应修改原有坐标，不要复制一个同名点盖在上面。

旧自动识别节点在 `named` / `unnamed` 数组中使用早期参考图的 **4684 × 1080** 坐标。若要用编辑器读到的当前坐标修改它们，换算为：

```text
旧 x = 当前 x × 4684 / 8192
旧 y = 当前 y × 1080 / 1900
```

注意分母仍为原图宽 8192，不是含补绘的 9216。新建在补绘区的节点直接放进 `manual` 数组，不使用旧坐标数组。

## 10. 保存、验证、撤回和提交

日常操作：

```bash
pnpm atlas:build
pnpm build
```

如果想检查同步工具本身（会在临时目录测试删岛、加曲线、变换及错误处理，不改母版）：

```bash
pnpm atlas:test
```

改坏了时，先在 Inkscape 撤销；已经保存则用**你自己修改前的备份**恢复 `atlas-editable.svg`，再运行 `pnpm atlas:build`。不要把 `atlas-reference.svg` 直接替换成母版：它没有新增的 1024 单位，画布尺寸不同。

提交时至少包含：

- `art-source/atlas-editable.svg`
- `public/assets/atlas.svg`
- `public/assets/atlas-regions.json`
- `docs/atlas-build-report.json`、`docs/vector-validation.json`
- 若动了节点，再包含 `src/nodes.ts`

无需提交 `.venv-atlas`、`node_modules` 或 `dist`。当前 GitHub Pages 工作流会自行构建。

**不要重新运行 `vectorize-atlas.py` 来同步手工修改。** 它只用于重新识别 JPG，会产出新的自动识别稿；日常修改只运行 `pnpm atlas:build`。

## 常见报错

| 提示 | 怎么处理 |
| --- | --- |
| 缺少离线制图环境 | 检查 Python，再运行一次 `pnpm atlas:setup` |
| 存在未闭合路径 | 回到节点工具，连接轮廓首尾 |
| 路径自相交 | 检查交叉节点，拆开打结部分 |
| 色块有重叠 | 删除重复对象，或用联合／差集处理，不要仅用上层填色遮盖 |
| 左右接缝不匹配 | 改动了 x=0 或 x=9216 边缘；两边必须保留相同端点和填色，建议撤销该次边缘修改 |
| viewBox 必须保持… | 恢复文档的 9216 × 1900 画布，不要「适配页面到选区」 |
| 网页没变化 | 确认保存的是母版、命令成功，并刷新浏览器；不要只修改显示用 SVG |
